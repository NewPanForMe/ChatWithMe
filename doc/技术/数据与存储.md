# 数据与存储

> 双库分工：PostgreSQL 存账号/会话/好友/通知/文件元数据；MongoDB 存聊天消息。

## PostgreSQL

- 主库：PostgreSQL + EF Core/Npgsql，连接串由 ToolsConsole 下发并 AES-256-GCM 解密，成功后本地加密缓存。
- 迁移按顺序执行（均在 `src/Server/ChatWithMe.Infrastructure/Migrations`）：

| 迁移 | 内容 |
| --- | --- |
| `20261116054648_InitialCreate` | `users`、`file_assets` |
| `20261116060400_AddRefreshTokens` | `refresh_tokens` |
| `20261117005612_AddConversations` | `conversations`、`conversation_members`、`users.role` |
| `20261117010337_AddFriendships` | `friendships`、`friend_requests`、`user_blocks` |
| `20261117020101_AddSessionVersion` | `users.session_version` |
| `20261117024943_AddAdminUsers` | `admin_users`（管理端账号） |
| `20261119005806_AddAnnouncements` | `announcements`（全员通知）及索引 |

- 执行迁移：`dotnet ef database update --project src/Server/ChatWithMe.Infrastructure --startup-project src/Server/ChatWithMe.Api`（需先配置设计时连接串或 `Security:DeliveryKey`）。

## MongoDB

- 连接名：`Security:ConnectionNames:Mongo = ChatWithMeMongo`（ToolsConsole 实测 `code=0`）。
- 远端下发的连接串不含 `authSource`，而账号建在 `admin` 库，驱动会拿业务库去认证 → `SCRAM-SHA-256` 认证失败。因此新增 `Mongo:AuthSource = admin`，由 `MongoConnectionSettings.BuildClientSettings` 在连接串未自带 `authSource` 时补齐；连接串自带则以其为准。
- 库名用小写 `chatwithme`：远端实例已存在该库，MongoDB 拒绝创建仅大小写不同的 `ChatWithMe`（报 `db already exists with different case`）。
- 集合 `cwm_messages`；索引 `ix_cwm_messages_conversation_sent_at_id`（ConversationId 升序 + SentAtUtc 降序 + Id 降序，对应复合游标翻页）与唯一索引 `ux_cwm_messages_conversation_client_message_id`，启动时由 `MongoIndexInitializer` 创建。旧索引 `ix_cwm_messages_conversation_sent_at` 已被前者取代，确认新索引生效后可手工 `dropIndex`。
- 该库中另有 `mylogs1`、`dbx_init` 两个与本项目无关的集合，**不要删除**。
