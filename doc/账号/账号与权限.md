# 账号与权限

> 本项目有**两套完全独立**的账号：聊天用户（`users`）与管理后台账号（`admin_users`）。两套凭据不能互相登录，接口、令牌声明与鉴权策略也分开。

## 1. 两套账号

| 维度 | 聊天用户 | 管理后台账号 |
| --- | --- | --- |
| 数据表 | `users` | `admin_users` |
| 注册 | `POST /api/users`（匿名） | 不开放注册，由管理员在「后端用户」页创建 |
| 登录 | `POST /api/auth/login` | `POST /api/admin/auth/login` |
| 令牌声明 `typ` | `user` | `admin` |
| 可访问 | 聊天、好友、会话、消息、通知 | 管理接口（用户、管理员、通知、在线管理） |
| 数量级 | 任意 | 少量，人工维护 |

管理端账号最小密码长度 8 位；聊天用户密码最小 6 位（`PasswordHasher`）。密码均以 PBKDF2-SHA256（10 万次迭代、16 字节盐）存储。

## 2. 令牌

| 项 | 规则 |
| --- | --- |
| 算法 | HS256，密钥 `Jwt:SigningKey`（user-secrets，启动 fail-fast） |
| access token | 15 分钟，**只存客户端内存** |
| refresh token | 7 天，只存 SHA-256 哈希；浏览器放 `HttpOnly; Secure; SameSite=Strict; Path=/api/auth` Cookie |
| 轮换 | 每次刷新吊销旧 refresh 并签发新的（旧值再用返回 401） |
| 声明 | `sub`、`email`、`jti`、`role`、`sv`（会话版本）、`typ`（`user`/`admin`） |

管理端令牌目前**没有 refresh 流程**：过期后需重新登录（后续可补）。

## 3. 鉴权与授权

- `Admin` 策略同时要求两个声明：`role=Admin` **且** `typ=admin`。聊天用户即使被改成 `role=Admin` 也进不了管理端。
- `SessionVersionMiddleware` 在每次认证请求时按 `typ` 校验：
  - `typ=user` → `users.session_version`
  - `typ=admin` → `admin_users.session_version` 且 `is_active=true`
  - 版本不一致或账号被禁用 → 立即 401「会话已失效」。
- 业务层权限：
  - 会话读写要校验成员；非成员 403，会话不存在 404。
  - 管理员可跨会话只读（审计）；发消息仍必须是成员。
  - 存在拉黑关系时，发消息/发好友申请/建单聊均 403。

## 4. 强制下线（踢人）

`POST /api/admin/users/{id}/kick`（Admin）一次性做三件事：

1. `users.session_version + 1` → 该用户所有旧 access token 下一次请求即 401，不必等 15 分钟过期；
2. 吊销该用户全部有效 refresh token；
3. 服务端 `Abort()` 该用户所有 SignalR 连接。

响应返回 `sessionVersion`、`revokedRefreshTokens`、`closedConnections`。桌面端收到 401/会话失效后会清理本地会话并回到登录页。

## 5. 账号管理

| 操作 | 接口 | 说明 |
| --- | --- | --- |
| 聊天用户列表 | `GET /api/users`（Admin） | 分页 + 关键字（邮箱/昵称，大小写不敏感） |
| 聊天用户详情 | `GET /api/users/{id}`（Bearer） | 聊天端解析昵称用 |
| 删除聊天用户 | `DELETE /api/users/{id}`（Admin） | 清理会话成员、空会话、refresh token、好友、申请、拉黑；Mongo 消息保留 |
| 管理员列表 | `GET /api/admin/accounts`（Admin） | 不回传密码哈希 |
| 新建管理员 | `POST /api/admin/accounts`（Admin） | 邮箱/名称/密码，密码 ≥8 |
| 删除管理员 | `DELETE /api/admin/accounts/{id}`（Admin） | 不能删除当前登录账号（409） |

## 6. 默认管理员（仅开发）

`appsettings.Development.json` 配置：

```json
"Security": {
  "BootstrapAdminEmail": "admin@chatwithme.local",
  "BootstrapAdminPassword": "Admin@12345"
}
```

启动时若 `admin_users` 为空则创建该账号；只创建一次，失败只记日志不阻塞启动。

**生产环境必须修改这两个值，或删除配置改为人工建号。** 密码写在配置文件里仅用于本地开发。

## 7. 常见状态码

| 场景 | 状态码 |
| --- | --- |
| 邮箱或密码错误 | 401（两种失败共用同一响应体） |
| 聊天用户访问管理接口 | 403 |
| 管理员账号登录聊天端 / 反之 | 401 |
| 删除当前登录管理员 | 409 |
| 邮箱已存在（注册/建管理员） | 409 |
| 令牌被踢下线 | 401「会话已失效」 |
